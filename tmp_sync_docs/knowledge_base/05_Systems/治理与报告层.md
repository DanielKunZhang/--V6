## 一句话结论

在 `2026-06-01` 新历史数据可用前，系统最重要的建设不是继续主观加新标的，而是把 `风控 / 归因 / review / overlay 样本登记 / 6月1日执行顺序` 固化成稳定证据链。

## 这层负责什么

- 把主仓、V6、Overlay、实验线放在同一治理视角里看。
- 把盈亏从“结果”拆成账户、sleeve、主题和执行过程。
- 把当周/当月现象推进成 backlog，而不是留在聊天里。
- 给 `2026-06-01` 的 V6-B 正式推进提前写好执行顺序。

## 这层不负责什么

- 不自动下真实交易单。
- 不自动扩容 V6 或把 challenger 升格为 baseline。
- 不因为某个 Radar 名字短期暴涨，就跳过 point-in-time 验证。

## 自动化边界

已经自动化的部分：

- `Central Risk Board` 已通过 launchd 每日自动运行并发送 HTML 邮件。
- `Performance Attribution`、`Overlay Journal`、`Monthly Research Review` 的脚本和输出格式已固定，可随时重跑。
- `V6 Weekly Review Board` 与 `V6 Research Backlog` 已能形成稳定 latest 指针。

仍然必须人工确认的部分：

- 是否根据红灯去调仓、降风险或修正主账本。
- 是否把某个研究现象升级成 challenger、baseline 替换或预算扩容。
- `2026-05-26` 的 V6-A cutover 决策。
- `2026-06-01` 的 V6-B 正式推进和之后任何真实账户动作。

## 你真正需要做什么

1. 每天看一次 `Central Risk Board` 的一行结论，确认问题是不是还集中在老风险上。
2. 每周看 `Performance Attribution` 和 `Weekly V6 Review Board`，把过程问题和结果问题分开。
3. 每月看 `Monthly Research Review`，只抓 `P0 / P1` backlog，不追所有支线。
4. Overlay 只认真实关闭样本，`watch` 或 `research_ready` 不能算策略成绩。
5. 到 `2026-06-01` 直接按执行卡推进，不再临时改变口径。
