## 目标

不是把所有脚本搬进来，而是让每套系统都有一张稳定的“系统卡片”。

每张系统卡片至少回答：

1. 这套系统负责什么
2. 不负责什么
3. 主要输入是什么
4. 主要输出是什么
5. 当前阶段是什么
6. 调用边界和放行条件是什么

## 跨系统统一锚

以下不是单独一个策略系统，而是所有系统共享的底层语言：

- `../00_System/价格_预期_现金流锚.md`
- `../00_System/候选分类与仓位上限总原则.md`

它约束的是：

- 当前价格已经反映了什么未来预期
- 我们认为哪里还有预期差
- 后续靠什么现金流/经营事实验证或证伪
- 候选先分为 `可做底仓 / 20X候选 / Radar或预期差候选 / 只研究不动作`
- 不同候选类型对应不同单票上限和整类风险预算
