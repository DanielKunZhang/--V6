# 2026Q1 13F 季度学习：第一轮

日期：2026-05-20  
范围：P0 管理人优先，P1 平台只做结构信号抽样。  
目标：吸收顶级基金产生超强 alpha 的原因，并转化为美股 Radar 的持仓选择能力。

## 一页结论

这轮 13F 学习不是为了抄仓，而是为了提炼 6 个可复用能力：

1. **宏观 regime 切换能力**：Duquesne 不只押 AI，还押 Brazil、Argentina、资源、等权指数和医疗右尾，说明顶级 alpha 来自“知道哪个市场阶段该找哪类资产”。
2. **高信念集中能力**：NTRA 在 Duquesne 中是明显大仓，Situational Awareness 对 AI data center / 电力 / 存储也有集中表达。超强 alpha 往往不是平均撒网，而是少数主线被验证后敢于集中。
3. **主线 + 对冲的双账本能力**：Situational Awareness、Tudor、Millennium、Citadel 都显示一个共同特征：可以看对主线，但同时用 put / ETF / index options 管理拥挤和尾部风险。
4. **反身性识别能力**：CRWV、IREN、APLD、CORZ、BE 这类 AI 基建票的关键不只是利润表，而是股价、融资、客户、capex、订单之间能否互相增强。
5. **右尾赔率识别能力**：SNDK、CRWV、BE、IREN、NTRA、INSM 不是传统稳态复利股，但可能在特定窗口提供不对称收益；我们必须区分“小仓右尾样本”和“可升级主仓候选”。
6. **拥挤度与退出纪律**：当同一主题被多家机构以 long + put/call 或 ETF put 表达，Radar 不能输出“追高”，而应输出 `crowded_but_valid / wait_for_pullback / event_gate_required`。

最终对我们系统的含义：

- 13F 学习要服务于 `Radar skill`，不是服务于买入冲动。
- 每个候选必须被标成：`research / watch / pullback / V6B_candidate / small_trial / manual_attack_candidate`。
- 当前不新增前台大仓；6月1日后把这些 skill 接入美股 Radar / V6-B universe refresh。

## Alpha 来源拆解

### 1. Situational Awareness：AI 主线集中 + beta 对冲

#### 它押的 alpha 来源

- AI data center / 新云 / 电力 / 存储 / 矿转算力的结构性需求。
- 通过 `BE / SNDK / CRWV / IREN / CORZ / APLD` 这类更有右尾弹性的环节表达 AI 基建。
- 同时用 `SMH / NVDA / ORCL / AVGO / AMD / MU / TSM / ASML` put 管理主线拥挤和半导体 beta 回撤。

#### 为什么可能有效

- AI CapEx 主线中，最大涨幅不一定只出现在最强龙头，也可能出现在瓶颈、供电、存储、新云、数据中心再定价层。
- 小票 / 中票受益链条可能比 mega-cap 更有赔率，但波动和融资风险更高。
- 用大票 / ETF put 对冲，可以在不放弃右尾的同时降低主题回撤。

#### 它如何控制失败风险

- 不是裸多整个 AI 链，而是 long 右尾 + put 对冲拥挤 beta。
- 这意味着它知道“方向对”和“短期价格风险高”可以同时成立。

#### 我们吸收成什么 Radar skill

- `crowding_hedge_skill`
- `institutional_put_hedge_signal`
- `asymmetric_payoff_skill`
- `reflexivity_skill`

#### 对我们候选池的处理

| 标的 | 角色 | 动作 |
|---|---|---|
| `SNDK` | 存储再定价右尾 | P1 复核，必须做估值现实检查 |
| `BE` | AI 电力 / 供电链 | P1 样本，等财报/订单验证 |
| `CRWV` | 新 AI 云平台 | P1 / 高波动，只进 Radar/V6-B，不进主观大仓 |
| `IREN / APLD / CORZ` | AI data center / 矿转算力 | P1/P2，强制融资、客户、capex、折旧反证 |
| `NVDA / AMD / AVGO / MU / TSM` | 主线核心 / 制造链 | 保留，但增加拥挤度惩罚 |

### 2. Duquesne：宏观 regime + 高信念集中

#### 它押的 alpha 来源

- 高集中度非 AI alpha：`NTRA`、`INSM`。
- AI 制造锚：`TSM`、STMicro。
- 非美 / 资源 / 再定价：`EWZ / Brazil`、`YPF`、Alcoa、Southern Copper。
- 市场广度：`RSP call`。

#### 为什么可能有效

- 超强 alpha 不一定来自单一热门主题，而来自“下一阶段哪个资产池被重估”。
- 当 AI beta 拥挤时，非 AI 的医疗、资源、非美、政策再定价可能提供更干净的赔率。
- 集中持仓说明其 alpha 来源是“选对少数高信念机会”，不是平均买一篮子热门股。

#### 它如何控制失败风险

- 主题分散：AI 制造、医疗、资源、非美、指数广度并存。
- 不把全部风险押在美股 mega-cap AI 上。
- 通过宏观分散降低单一主题拥挤崩塌风险。

#### 我们吸收成什么 Radar skill

- `macro_regime_skill`
- `concentration_conviction_skill`
- `non_ai_alpha_watch`
- `theme_concentration_rank`

#### 对我们候选池的处理

| 标的 / 表达 | 角色 | 动作 |
|---|---|---|
| `TSM` | AI 制造锚 | 维持 V6-B / Radar P1 |
| `NTRA / INSM` | 非 AI alpha 样本 | 只进样本库，先不进主仓 |
| `EWZ / YPF / Alcoa / SCCO` | 宏观 regime 样本 | 用于训练 macro_regime，不直接交易 |
| `RSP` | 市场广度样本 | 用于判断 mega-cap 外扩散是否成立 |

### 3. Tudor：风险优先 + 期权结构表达

#### 它押的 alpha 来源

- 不是简单押方向，而是通过 `IWM puts / calls`、`QQQ puts / calls` 表达风险、波动和趋势。
- 个股层面大量 long + call + put 并存，例如 ADBE、AMD、GOOGL。

#### 为什么可能有效

- 顶级宏观交易不是只问“涨不涨”，而是问“赔率、波动、风险和路径是否匹配”。
- 同一标的可以既是看多对象，也是对冲对象或波动交易载体。
- 期权结构能把观点拆成方向、时间、波动和尾部风险。

#### 它如何控制失败风险

- 用指数 / ETF 层管理大盘和风格暴露。
- 个股层面不把单票方向暴露解释得过于简单。
- 通过多层期权结构控制路径风险。

#### 我们吸收成什么 Radar skill

- `institutional_hedge_signal`
- `macro_regime_skill`
- `invalidation_skill`
- `event_gate_required`

#### 对我们候选池的处理

| 标的 / 表达 | 角色 | 动作 |
|---|---|---|
| `ADBE` | 高流动性软件风险载体 | 不因 13F 改变仓位纪律，仍等 Q2 / CEO gate |
| `AMD / GOOGL / QQQ / IWM` | 风格 / beta / 波动样本 | 用于判断 risk regime 和拥挤度 |
| `QQQ / IWM puts-calls` | 宏观风险温度计 | 加入 Radar 宏观层，不当个股信号 |

### 4. Point72 / Millennium / Citadel：平台宽度与拥挤度

#### 它们押的 alpha 来源

- Point72：`NVDA / AMZN / ANET / SPY calls`，显示 AI、mega-cap 和 AI networking 仍有平台资金宽度。
- Millennium：`IWM puts / IVV / NVDA puts / QQQ puts`，显示指数和科技 beta 对冲需求强。
- Citadel：`SPY puts / QQQ puts / SPY calls / TSLA calls`，更多是期权和流动性结构。

#### 为什么可能有效

- 平台型基金集合了大量 pod 的风格，单一持仓方向含义弱，但能反映主题宽度、交易拥挤和流动性集中。
- 当多平台都在同一主题上用期权 / ETF 表达，说明这个主题已经是主流战场。

#### 它们如何控制失败风险

- 多 pod、多策略、多空和衍生品分散。
- 大量 ETF / index / options 用于动态管理 beta。

#### 我们吸收成什么 Radar skill

- `theme_breadth_signal`
- `crowding_penalty`
- `institutional_validation`
- `liquidity_and_options_attention`

#### 对我们候选池的处理

| `NVDA / AMZN` | mega-cap AI / cloud 样本 | 主题确认，不新增主观追高 |

## 我们的 Radar 规则升级

### 新增字段

| 字段 | 含义 | 第一轮样本 |
|---|---|---|
| `macro_regime_fit` | 当前宏观环境是否支持这类交易 | Duquesne 的 EWZ / RSP / YPF / commodities |
| `institutional_validation` | 是否被高质量机构作为主题样本验证 | SA 的 AI infra、Point72 的 NVDA/ANET |
| `institutional_hedge_signal` | 是否有显著 put/call / ETF 对冲结构 | SA、Tudor、Millennium、Citadel |
| `crowding_penalty` | 主线强但交易拥挤时的惩罚 | NVDA / AMD / AVGO / TSM / QQQ / SMH |
| `reflexivity_score` | 股价、融资、客户、订单、capex 是否互相增强 | CRWV / IREN / APLD / CORZ / BE |
| `non_ai_alpha_watch` | 非 AI 高质量 alpha 样本层 | Duquesne 的 NTRA / INSM |
| `theme_breadth_signal` | 主题是否从少数龙头扩散到更宽资产池 | Point72 / Millennium / RSP |
| `position_role` | 输出角色，不直接输出买卖 | research / watch / pullback / V6B_candidate / manual_attack_candidate |

### 标准输出结构

以后每次 `更新13F学习`，报告必须用这个结构：

1. 这批基金在押什么 alpha 来源？
2. 这个 alpha 来源为什么可能有效？
3. 它们如何控制失败风险？
4. 我们能吸收成哪个 Radar skill？
5. 哪些标的进入候选池，哪些只是样本，不进入交易？
6. 对现有持仓有没有确认或反证？
