# A股短线 Radar 系统规格 v1

> 创建日期：2026-05-18
> 状态：设计规格，持续迭代

---

## 0. 系统目标

本系统目标不是预测每一只短线牛股，而是在严格风控下，用小仓位、可复盘的主线交易能力，长期提高组合总体收益率；任何不能被记录、复盘和迭代的交易，都不属于本系统。

---

## 0.1 复盘驱动进化原则

本系统不是一次性写死的交易规则，而是复盘驱动的迭代系统。V6-A、美股 Radar、A股 Radar 都必须通过持续复盘来优化，但优化必须有证据、有记录、有边界。

**核心原则：**

- 每一次交易、错过、误判、剔除、止损、踏空，都必须能被记录。
- 规则优化只能来自样本复盘，不能来自单次情绪反应。
- 所有改动必须说明：触发事件、原规则缺陷、新规则、预期改善、潜在副作用。
- 不允许因为一次失败推翻整套系统。
- 不允许因为一次成功放大仓位或放松风控。
- 没有复盘记录的经验，不能写入系统规则。
- 任何新规则必须先进入观察期，再进入执行期。
- 优化目标不是提高单次收益，而是提高长期期望值、降低最大回撤、减少规则外交易。

**适用范围：**

- `V6-A`：复盘信号新鲜度、执行偏差、真实成交、滑点、回撤、release gate 有效性。
- `美股 Radar`：复盘主题扩散、右尾候选、买点有效性、估值现实、是否追高。
- `A股 Radar`：复盘主线识别、角色判断、纯概念剔除、计划内买点、止损执行。

## 1. 系统边界

- 当前阶段：Phase 1A，FutuAPI 拉行情 + 长江证券手动下单。
- 不自动下单，不接 PTrade/QMT 委托接口。
- 不服务主仓价值投资，不影响腾讯、PDD、NVDA、泡泡玛特等主仓决策。
- 不做打板系统，不做纯情绪接力，不追一字板。
- 不接纳无业绩、订单、客户验证、产能瓶颈、政策落地、财报改善或真实供需变化支撑的纯概念炒作标的。
- 典型硬排除：巨力股份型纯概念炒作。

## 2. 模块结构

### 2.1 主线识别层

**输入：**
- 涨幅榜、成交额榜、换手率榜
- 板块/概念强度
- 同主题多股共振
- FutuAPI K线、成交额、MA5/MA10/MA20
- X Radar / Friend Alpha / 人工观察
- 产业事件、政策事件、财报、订单催化

**输出：**
- `NoTheme`
- `ThemeWatch`
- `ThemeConfirmed`
- `ThemeRetreat`

**主线成立条件：**
- 同主题至少 2-3 只股票同步放量上涨
- 龙头成交额和涨幅居前
- 板块强于指数
- 不是单日孤立脉冲
- 至少有一条可验证产业/业绩/订单/政策支撑

**主线否决条件：**
- 只有单票异动
- 只有题材标签或传闻
- 一字板无法参与
- 龙头高开低走且放量滞涨
- 大盘系统性破位

## 3. 标的入池规则

**候选状态：**
- `NoNewCandidate`
- `ThemeWatch`
- `AddToRadarCandidate`
- `Rejected`

**入池必须满足：**
- 明确主题
- 明确代码
- 明确角色假设：龙头 / 中军 / 补涨 / 待定
- 明确触发理由
- 明确未来 1-3 个交易日验证点
- 明确不属于纯概念炒作
- 用户人工确认后才能写入 `radar_astock.json`

**硬排除：**
- 无业绩/订单/产业验证支撑
- 互动平台概念、市场传闻、资金博弈
- 单日爆量冲高回落
- 一字板连续顶涨无法买入
- 已被主线淘汰的旧热点补涨

---

## 4. 角色定义

| 角色 | 描述 |
|---|---|
| 龙头 | 主题内成交额、涨幅、趋势强度最强，能带动板块 |
| 中军 | 成交额稳定、走势跟随龙头，弹性弱但不掉队 |
| 补涨 | 前期弱于龙头，中后段补涨，仓位上限低于龙头/中军 |
| 待定 | 逻辑存在但走势未确认 |
| 退出 | 连续走弱、放量滞涨、主线退潮或证伪 |

---

## 5. 买点类型

**允许买点：**

| 买点类型 | 描述 |
|---|---|
| `pullback_5d` | 回踩 MA5 不破，量能缩至 5日均量 0.7x 以下 |
| `pullback_10d` | 回踩 MA10 不破，量能缩至 5日均量 0.7x 以下 |
| `breakout_confirmed` | 放量突破平台，但不能是一字板或高开低走 |
| `leader_confirmation` | 龙头确认后，中军缩量回踩 |
| `theme_retreat_repair` | 主线退潮后龙头先企稳，板块重新放量 |

**禁止买点：**
- 单日暴涨后追高
- 一字板排队
- 纯消息刺激高开
- 龙头已经分歧时买补涨
- 大盘系统性下跌时扩大仓位

## 6. 仓位纪律

**Phase 1A 训练期：**

以下百分比均指占 `A股 Radar 子账户资金` 的比例，不是占全资产或主仓比例。

| 仓位类型 | 上限 |
|---|---|
| A股 Radar 总资金 | 5万以内 |
| 单票初始试错 | 总 Radar 资金 10%-15% |
| 龙头验证仓 | 30% |
| 中军 | 20% |
| 补涨/待定 | 10% |
| 同主题总仓位 | 50% |
| 单日新增仓位 | 30% |

连续两笔亏损后，暂停新开仓 2 个交易日。

**任何时候：**
- 不允许因"看起来很强"突破仓位上限。
- 不允许用主仓资金补 Radar 仓。
- 不允许亏损后加倍摊平。

### 6.1 观察期候选模式

当前 20 个交易日观察期内，所有模式真实仓位均为 `0`。

| 模式 | 含义 | 仓位 |
|---|---|---|
| `AMBUSH` | 前置信号强，但主线尚未完全高潮；只记录模拟触发 | `0` |
| `CONFIRM` | 主线已确认；只等分歧回踩、突破回踩或中军确认；只记录模拟触发 | `0` |
| `WATCH_CONFIRM` | 主线有强度，但买点/数据/风险不满足交易 | `0` |
| `WATCH_ONLY` | 只记录表现，不交易 | `0` |
| `WATCH_ONLY_PLUS` | 复盘证明普通 `WATCH_ONLY` 过严，但仍因缺 K 线/观察期不能交易；优先补数据并次日重点模拟确认 | `0` |

### 6.2 数据缺口容错规则

`WATCH_ONLY_PLUS` 是复盘反哺模式，不是买入模式。它解决的是“主题和个股都强，但因为本地 K 线缺失只能观察，事后被判定为规则过严”的问题。

晋级条件必须同时满足：

- 收盘复盘分类为 `规则过严`。
- 原计划动作包含 `仅实时观察` 或 `需补K线`。
- 主题分不低于 `25`，且主题阶段包含 `主升`。
- 标的角色为 `龙头` 或 `中军`，不适用于普通补涨和后排。
- 当日成交额不低于 `20亿 RMB`。
- 当日涨幅不低于 `8%`。

晋级后的系统动作：

- 优先补齐最近 60 个交易日 K 线。
- 次日只做模拟低吸/突破回踩触发记录。
- 观察期内真实仓位仍为 `0`。
- 若次日主题退潮、高开加速、开盘冲高回落或无法补齐数据，退回普通 `WATCH_ONLY`。

每日闭环由 `a_share_radar_daily_loop.py` 执行：

1. 用 OpenD 最新快照完成复盘。
2. 运行 `a_share_radar_feedback.py` 生成反哺清单。
3. 运行 `a_share_radar_backfill.py` 只对 P0 / `WATCH_ONLY_PLUS` 标的补 K 线。
4. 重新生成晚间指导，把反哺和补 K 线状态显示出来。

历史 K 线额度只能用于 P0 反哺标的，不允许在本闭环里做全市场泛化补数。

## 7. 止损 / 退出规则

**个股退出：**
- 跌破买入日低点或前一关键低点，触发止损。
- 买入后 2 个交易日未按预期走强，降级观察。
- 开高走低 + 放量滞涨，进入 `DIVERGE_WARNING`。
- 连续 2 日弱于主题，降级或退出。
- 证实为纯概念炒作，直接 `DISABLED`。

**主题退出：**
- 龙头连续 2 日分歧。
- 主题成交额明显萎缩。
- 新主线替代旧主线。
- 指数系统性破位。
- 政策/订单/业绩催化被证伪。

## 8. 情绪周期状态机

**市场状态：**
- `RISK_ON`
- `NEUTRAL`
- `RISK_OFF`

**主题状态：**
- `INCUBATION`
- `CONFIRMED`
- `CLIMAX`
- `DIVERGENCE`
- `RETREAT`

**行为矩阵：**

| 市场状态 | 主题状态 | 允许行为 |
|---|---|---|
| `RISK_ON` | `CONFIRMED` | 允许计划内买点 |
| `RISK_ON` | `CLIMAX` | 不追高，只等回踩 |
| `NEUTRAL` | `CONFIRMED` | 降低仓位，只买龙头/中军 |
| `NEUTRAL` | `DIVERGENCE` | 停止新增 |
| `RISK_OFF` | 任何 | 不新开仓，只处理退出 |

## 10. 样本审计

**20个交易日审计：**
- 是否能稳定识别主线
- 是否能剔除纯概念炒作
- 是否能及时发现分化
- 是否存在频繁改规则

**50笔交易审计：**
- 胜率
- 盈亏比
- 平均持有期
- 最大单笔亏损
- 最大连续亏损
- 最大回撤
- 规则执行偏差率
- 是否具备正期望

**没有 50 笔正期望前：**
- 不扩大资金
- 不接自动委托
- 不把 Radar 收益纳入生活费计划

---

## 10.1 规则变更审计

每次规则变更必须记录：

| 日期 | 系统 | 触发事件 | 原规则问题 | 新规则 | 预期改善 | 风险/副作用 | 是否进入执行 |
|---|---|---|---|---|---|---|---|

**规则变更分三级：**

| 级别 | 描述 |
|---|---|
| `Observation` | 只观察，不影响交易 |
| `CandidateRule` | 进入候选规则，连续验证 5-10 个样本 |
| `ActiveRule` | 正式执行规则，必须写入 SOP 或代码 |

**禁止事项：**
- 禁止盘中临时改规则。
- 禁止为了合理化一次亏损而改规则。
- 禁止为了追一个热点而放宽入池标准。
- 禁止没有样本证据就提高仓位。

## 12. 禁止事项

- 禁止因单日涨幅加入观察池。
- 禁止买入无验证支撑的纯概念炒作。
- 禁止打板、一字板排队。
- 禁止亏损摊平。
- 禁止主仓资金补 Radar。
- 禁止未复盘就扩大仓位。
- 禁止把 Radar 结论用于价值主仓。
- 禁止没有记录的口头交易。
