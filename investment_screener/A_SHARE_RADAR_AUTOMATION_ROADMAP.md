# A股 Radar 量化辅助交易系统 — 设计路线图

> 创建日期：2026-05-18
> 当前阶段：Phase 1A（FutuAPI 信号 + 长江证券手动下单，不接券商委托接口）
> 关联数据文件：`radar_astock.json`（观察池）
> 关联复盘命令：`~/.claude/commands/A股Radar复盘.md`
> 长江证券反馈：PTrade 极速版门槛约 100 万信用账户净资产；当前 5 万训练资金阶段不接 PTrade

---

## 核心原则

**量化的目标不是"更快下单"，是"系统性减少错单"。**

A股短线最大风险：买太多、买太急、在退潮期还按主升浪逻辑操作。
自动化优先级：过滤信号 > 生成执行卡 > 半自动提醒 > 最后才考虑自动委托。

---

## 一、三阶段路线

### Phase 1A：信号量化，不接交易（当前执行）

**条件**：不需要长江证券接口，富途 OpenD 或公开数据即可。

目标：
- 每日收盘后自动计算信号字段
- 输出结构化 `signal_state` 和 `setup_type`
- 生成 Markdown 执行卡
- 执行卡进入 Daily Board（`events_calendar.json`）

交付物：
- `radar_signal_engine.py`：读取 `radar_astock.json`，拉行情，计算信号，输出执行卡
- 执行卡存为 `radar_exec_card_YYYYMMDD.md`

**你手动在长江证券客户端下单。系统不触碰任何委托接口。**

---

### Phase 1B：半自动执行卡强化（20个交易日后评估）

**前提**：至少完成 20 个交易日的 A股 Radar 复盘，确认主线/角色/买点判断稳定。

目标：
- 执行卡从 Markdown 扩展为 Markdown + CSV
- 每日自动列出 WATCH / BUY_CANDIDATE / DIVERGE_WARNING / EXIT_WATCH
- 继续用 FutuAPI 拉行情，长江证券手动下单
- 不接 PTrade，不接任何委托接口

进入条件：
- 20 个交易日复盘记录完成
- 至少出现过主线成立、内部分化、退出观察三类样本
- `radar_astock.json` 字段稳定，不再频繁改 schema

---

### Phase 2：接行情/持仓，只生成执行卡，不自动下单

**前提**：A股 Radar 资金接近 50 万，且长江证券确认支持 QMT / PTrade / miniQMT Python API。

目标：
- 评估是否用长江行情替代富途拉 A股数据（降低对富途额度的依赖）
- 读取长江账户持仓和资金余额
- 自动识别计划内买点是否触发
- 执行卡包含"当前持仓是否已有"的判断

新增能力：
- 持仓自动对比信号（避免重复建仓）
- 资金可用量自动计算建议仓位金额
- 收盘后自动生成复盘 summary 草稿

**所有委托仍由人工在长江客户端完成。**

---

### Phase 3：小额半自动或全自动（严格门槛，当前锁定）

**进入条件（所有条件必须同时满足，缺一不可）：**

- [ ] 累计 **≥ 50 笔**手动复盘记录（含完整进出时间、价格、仓位、信号类型）
- [ ] 实盘验证：胜率 ≥ 55%，盈亏比 ≥ 1.5，期望值 > 0
- [ ] 最大回撤有上限，且已出现亏损样本并完成规则修正
- [ ] 平均持有期明确（短线 1-3 天 or 趋势 1-2 周，二选一）
- [ ] 硬止损规则已写入代码（单笔最大亏损、单日最大亏损）
- [ ] 主题退潮自动停止规则测试通过（≥3 次历史情景验证）
- [ ] 长江证券 PTrade / QMT 门槛已满足并完成合规开通（当前 PTrade 极速版约需 100 万信用账户净资产）
- [ ] 自动委托只使用 **≤ 2 万**额度试跑，通过后才讨论扩规模

**当前状态：🔒 Phase 3 锁定，不讨论自动下单实现。**

---

## 一点五、资金规模与接口升级路线

| A股 Radar 资金规模 | 推荐模式 | 原因 |
|---|---|---|
| 5万-20万 | FutuAPI 信号 + 长江手动下单 | 当前验证期，自动下单工程风险大于收益 |
| 20万-50万 | 半自动执行卡 + 手动下单 | 强化信号、复盘、风控，不急着接券商 |
| 50万-100万 | 开始评估 PTrade / QMT 接入 | 规模接近接口门槛，可调研行情/持仓读取 |
| 100万以上 | 可申请 PTrade，但先只接行情/持仓 | PTrade 是规模化工具，不是验证期工具 |
| 100万以上且50笔实盘正期望 | 才评估小额半自动/自动委托 | 自动化必须服务成熟系统，而不是替代判断 |

当前结论：从 5 万做到 100 万之前，优先使用 FutuAPI 半自动化 + 长江证券手动交易。

## 二、信号字段设计

### 2.1 radar_astock.json 扩展结构

在现有结构（`name / role / added_date / note`）基础上，每只股票新增以下字段。
**不破坏现有字段，新增字段作为可选扩展。**

```json
{
  "SH.688017": {
    "name": "绿的谐波",
    "role": "龙头",
    "added_date": "2026-05-18",
    "note": "20260518 午盘 40亿成交量 +7.2%，龙头地位确认",

    "signal_state": "WATCH",
    "setup_type": null,
    "trigger_price": null,
    "invalidation_price": null,
    "max_position_pct": 30.0,
    "review_required": false,
    "last_signal_date": "2026-05-18"
  }
}
```

### 2.2 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 富途格式股票代码，如 `SH.688017` |
| `name` | string | 中文名称 |
| `role` | string | 龙头 / 中军 / 补涨 / 待定 / 退出 |
| `theme` | string | 所属主线，如"精密传动/谐波减速器" |
| `signal_state` | string | 见下表 |
| `setup_type` | string / null | 见下表，无形态时为 null |
| `trigger_price` | float / null | 买点触发价（如回踩 MA10 的目标价位） |
| `invalidation_price` | float / null | 买点失效价（跌破则取消当日信号） |
| `max_position_pct` | float | 该票最大仓位占 Radar 资金池的百分比；Phase 1 默认不超过 30.0 |
| `review_required` | bool | 是否在下次复盘前需要人工复核 |
| `last_signal_date` | string | 最近一次信号更新日期 |
| `note` | string | 追加式备注，格式：`YYYYMMDD 描述` |

### 2.3 signal_state 枚举

| 值 | 含义 |
|---|---|
| `WATCH` | 主线成立，无明确买点，持续观察 |
| `BUY_CANDIDATE` | 出现计划内买点，执行卡已生成，等待人工确认 |
| `HOLD` | 已持有，主线未退潮，不需要新操作 |
| `DIVERGE_WARNING` | 出现分歧信号（开高走低/量缩），暂停新操作 |
| `EXIT_WATCH` | 退出信号触发，人工确认是否清仓 |
| `DISABLED` | 暂时移出信号计算（主题休眠/个股特殊情况） |

### 2.4 setup_type 枚举

| 值 | 描述 | 典型触发条件 |
|---|---|---|
| `breakout` | 放量突破前高 | 成交额 > 5日均量 1.5x，突破近期高点 |
| `pullback_5d` | 回踩5日线 | 现价 ≤ MA5 × 1.01，量能收缩至 < 0.7x |
| `pullback_10d` | 回踩10日线 | 现价 ≤ MA10 × 1.01，量能收缩至 < 0.7x |
| `leader_confirmation` | 龙头强势日中军顺势 | 龙头涨幅 > 5%，中军同向且未开高走低 |
| `theme_retreat` | 主题整体回调后企稳 | 全主线2日下跌后出现缩量止跌，龙头不破前低 |

## 三、手动执行卡格式

每次 `BUY_CANDIDATE` 信号触发时，`radar_signal_engine.py` 输出以下格式的 Markdown 文件：

```
存储路径：/Users/zhangkun/WorkBuddy/程序化/量化程序/investment_screener/exec_cards/
文件命名：radar_exec_card_YYYYMMDD.md
```

---

```markdown
# A股 Radar 执行卡 — YYYY-MM-DD

> 生成时间：收盘后 / 信号触发时
> 主线：[主题名称]
> 主线状态：成立 / 分歧预警 / 退潮

---

## 今日候选

| 标的 | 代码 | 角色 | 信号 | 形态 |
|---|---|---|---|---|
| [名称] | [代码] | 龙头/中军 | BUY_CANDIDATE | pullback_10d |

---

## 触发条件

- 形态：[setup_type 描述]
- 触发价：≤ [trigger_price] RMB
- 量能要求：量能比 < 0.7（缩量回踩）
- 主线确认：龙头今日未开高走低

---

## 买点

- 目标买入区间：[trigger_price - 1%] ～ [trigger_price]
- 优先买入时机：开盘30分钟内 / 尾盘缩量企稳

---

## 止损 / 失效条件

- 失效价：[invalidation_price]（跌破则今日信号作废）
- 止损逻辑：跌破前低 [X] 日低点，不等反弹，直接止损
- 主线失效：龙头当日开高走低 → 取消当日所有候选

---

## 最大仓位

- 本票上限：Radar总资金 × [max_position_pct]%
- 参考金额（5万账户）：约 `50000 × max_position_pct / 100` RMB
- 禁止超仓：即使信号强，单票不超过上限

---

## 是否允许今日执行

- [ ] 主线龙头今日未开高走低
- [ ] 大盘未出现系统性破位（沪指 / 创业板指 / 科创50）
- [ ] Radar 当前总仓位未超上限
- [ ] 本票未处于 DIVERGE_WARNING 或 EXIT_WATCH 状态

> 以上四项全部勾选，才允许执行。任一未满足，本日不操作。

---

## 人工确认项（下单前必须检查）

- [ ] 确认当前价格在触发区间内
- [ ] 确认未持有该票（避免重复建仓）
- [ ] 确认主线今日整体表现正常
- [ ] 确认账户可用资金充足

---

## 收盘复盘项

- [ ] 是否成交？成交价：____
- [ ] 收盘时盈亏：____
- [ ] 信号是否兑现？是 / 否 / 部分
- [ ] 如未成交，原因：____
- [ ] 明日是否继续有效？是 / 否
- [ ] 更新 radar_astock.json 中该票的 signal_state 和 note

---

## 今日无操作标的

| 标的 | 信号状态 | 原因 |

| [名称] | DIVERGE_WARNING | 开高走低，暂停操作 |
```

## 四、风控红线

### 当前阶段（Phase 1）硬规则

| 规则 | 内容 |
|---|---|
| **禁止自动下单** | Phase 1A/1B 严禁任何程序化委托接口调用，所有下单在长江客户端手动完成 |
| **单票最大仓位** | Radar 总资金的 30%（5万账户 ≈ 1.5万/票） |
| **Radar总仓位上限** | 不超过总资产的 5-8%（约 2.5-4万） |
| **同时持仓数** | 不超过 3 只（同一主题内集中，不分散） |
| **单日最大亏损** | Radar 总仓位的 5%（约 1250-2000 RMB），触达则当日停止新操作 |

### 暂停信号触发规则

| 暂停条件 | 暂停范围 | 恢复条件 |
|---|---|---|
| 龙头连续 2 日开高走低 | 暂停该主题所有 BUY_CANDIDATE | 龙头出现缩量企稳信号 |
| 主线整体单日成交额萎缩 > 50% | 暂停该主题所有操作 | 成交额恢复 + 龙头重新放量 |
| 大盘单日跌幅 > 2.5% | 暂停所有 A股 Radar 操作 | 次日盘面确认稳定 |
| 连续 3 笔亏损 | 暂停新建仓操作，仅允许止损出场 | 人工复盘、规则修正后重启 |

### 不混用原则

- **A股 Radar 资金池独立**，与主仓（美股/港股价值投资）不混用
- Radar 持仓不计入价值投资仓位上限，分开统计
- 不用 Radar 逻辑操作主仓，不用价值投资逻辑操作 Radar

### 已知信息

- 适用客户：量化、程序、可转债套利、拆单、篮子交易等。
- 当前判断：PTrade 适合作为未来规模化工具，不作为当前 A股 Radar 验证期前置条件。

### 基础接口

- [ ] **支持哪种接口？** QMT / miniQMT / PTrade / 其他（三者 Python 能力差异很大）
- [ ] **是否支持 Python API？** 能否本地 `pip install` + 脚本运行？
- [ ] **是否有官方文档或 SDK 下载地址？**

### 行情能力

- [ ] **实时行情**：能否获取 A股实时报价（涨跌幅、现价、买卖盘）？
- [ ] **历史 K线**：能否获取日线/分钟线历史数据？有无时间/条数限制？
- [ ] **成交额/成交量**：能否获取逐日成交额数据？

### 交易能力（Phase 2+ 使用，当前仅调研）

- [ ] **持仓查询**：能否读取账户持仓和资金余额？
- [ ] **委托下单**：支持限价单 / 市价单？
- [ ] **撤单**：支持程序化撤单？
- [ ] **条件单**：支持止损单或价格触发单？
- [ ] **是否有频率限制**：每秒/每分钟最多请求多少次？

### 账户与合规

- [ ] **个人账户开通门槛**：资产要求多少？需要什么条件？
- [ ] **是否有模拟/沙盒环境**：能否在不用真实资金的情况下测试 API？
- [ ] **是否需要单独签署协议**：量化/程序化交易协议？
- [ ] **激活时间**：申请到可用大约需要几个工作日？

### 过渡方案（若接口短期无法开通）

若长江接口开通周期较长，可先用以下方式过渡：
1. 富途 OpenD 拉 A股行情（需注意额度限制）
2. 信号引擎生成 CSV 执行清单，手动在长江客户端按清单操作
3. 不接任何券商 API，纯信号辅助，人工 100% 执行

## 六、与现有系统集成

| 系统组件 | 当前角色 | 未来角色（Phase 2+） |
|---|---|---|
| `radar_astock.json` | 观察池（代码/角色/备注） | 扩展信号字段，成为信号状态数据库 |
| `A股Radar复盘.md` | 人工复盘 SOP | 收盘后由 `radar_signal_engine.py` 辅助生成草稿 |
| `events_calendar.json` | 复盘提醒入口 | 增加"今日 Radar 执行卡已生成"类型事件 |
| `morning_brief.py` | 早间总览 | 增加展示 Radar 今日信号状态（只展示，不决策） |
| `system_health_check.py` | 系统文件检查 | 检查 `radar_astock.json` 与 A股 Radar SOP/roadmap 是否存在 |
| `watchlist.json` | 价值投资估值库 | 保持独立，不与 Radar 混用 |

### 集成原则

- **单向数据流**：`radar_astock.json` → `signal_engine` → `exec_card.md` → 人工执行 → 复盘记录写回 `note`
- **不修改现有运行脚本**：`morning_brief.py` / `central_risk_board.py` 等保持不变，通过新增函数或独立脚本集成
- **执行卡不自动推送**：Phase 1 阶段执行卡只生成文件，不触发任何通知或委托
