Dingcle Capital 目标函数

在不触发永久性资本损失风险的前提下，尽可能提高单位风险收益率和资金周转效率； 用价值主仓保证长期生存，用 V6-A 提高小资金阶段的资金效率；V6-B / 美股 Radar 先作为研究输入，不占当前预算。

最高目标函数： 投资是热爱的事业，但不能毁掉生活。长期目标是学习巴菲特 / 芒格 / 段永平式复利； 小资金阶段允许通过 V6、Radar 和定义风险 Overlay 争取 45%-55%+ 的右尾年份， 但这只能是受控进攻的奖励，不能成为常态预期，更不能反过来破坏主仓安全、生活质量和系统纪律。
投资哲学总纲： 以价值投资为底层世界观，以系统化风控和量化工具提高资本配置效率，在不牺牲长期安全性的前提下追求更高复利。
主从关系写死：价值主仓是主哲学和大资金底盘；V6 是规则化收益增强工具；Radar 是研究供给链和主线发现工具；Overlay / 期权是定义风险表达层；Micro Futures 只属于独立学费仓。所有增强器都必须服从长期复利、风险优先、少数高质量决策和可关闭可复盘原则。
2026-05-19 占比再分配方向： 组合不改成纯趋势基金，但主仓内部要从“便宜、稳、低反馈资产过重”逐步调整为 底仓 + 进攻仓。底仓负责不死，进攻仓负责推动净值增长。 执行上不是卖掉价值哲学，而是把新增资金、超配回流资金和低优先级仓位回收资金，优先分配给已经通过财报、产业趋势和估值纪律验证的进攻仓资产。
动态占比总原则： 当前 300 万 RMB 左右本金阶段，组合应比 3000 万以后更主动地动态调整占比；所有系统、评估和复盘都要服务于 在不破坏底层价值哲学的前提下，提高资本配置效率。 300 万-1000 万阶段允许更高反馈、更高频的占比调整；1000 万-3000 万阶段逐步降低换手；3000 万以上再明显转向慢调整、低换手和更低永久损失风险。 动态调整必须由财报兑现、估值位置、主题强度、拥挤度、V6/Radar 信号和组合回撤共同触发，不能由短期焦虑或身边人收益刺激触发。

  • 适合放：`卫星实验仓 / 少数特殊高赔率机会 / 周期错位窗口`。
  • 纪律：这层必须预算化存在，不能吞掉整个系统，也不能被错误地当成底仓或进攻仓。

财报微调的正式纪律

  1. 每月一次结构检查：只看真实最新仓位、永久席位偏离、现金与灵活席位占比。
  2. 每季一次财报验证：重点先看 腾讯 / PDD / ADBE / 泡泡玛特 / V6-B 资源池，再看 NU / 美的 / NVDA。
  3. 主仓与 V6 重叠时，更新口径向上兼容：若同一股票同时存在于主仓与 V6，必须按主仓 thesis完整同步财报与经营变化，不允许因为 V6 自动仓身份而忽略主仓更新。
  4. 所有持仓与候选都执行非财报验证：不能只看季报/年报，必须同时搜索最新外部真实数据，确认财报与现实世界是否互相印证。
  5. 单一数据只能做线索：任何一条社媒热度、单个榜单、一次渠道反馈或一篇报道，都不能单独推动估值上修或仓位升级。
  6. 非财报验证必须标注来源与日期：优先使用最近 `30-60天` 的数据，且至少覆盖 `官方披露/IR` + `渠道/平台/行业客观数据` 或 `第三方旁证`；能覆盖三类更好。
  7. 行业重点要因标的而变：消费看渠道/复购/热度，平台看用户/变现/生态，软件看留存/采用/定价，金融看坏账/获客/监管，周期看价格/订单/库存/产能。
  8. 最终动作必须压缩：研究可以厚，但最后 `买 / 加 / 减 / 不动` 只能依赖少数关键变量，不允许把成功建立在过长的串联前提上。
  9. 只允许两类动作：结构性减仓、击球区建仓。除此之外，不做第三种情绪化动作。
  10. 微调，不推翻：财报后允许调价格带、调仓位上限、调灵活席位，但不轻易推翻永久席位框架。
  11. 若财报与价格同时恶化：先降级，再谈加仓，不允许“越跌越信仰”。
反纪律提醒：不能因为想快点实现 6 年 4 倍，就在非击球区用财报“自我说服”强行上仓位。
总验证纪律： 只有当价格更舒服 + 最新外部真实数据验证未转弱，最好还在增强时，才允许提高仓位。 这条适用于所有标的；只是不同公司看的外部信号不同。
综合判断纪律： 我们允许 `毛估估`，但这里的意思是：在财报、外部现实、行业位置、管理层、赔率与下行风险都看过后，做综合区间判断；不是凭单一数据或单一模型拍脑袋。
反复杂化决策纪律： 最终每次动作前，必须明确：`这笔钱主要靠哪 1-2 个变量赚钱`。如果一个动作需要依赖 `5-6` 个以上前提同时成立，默认降级为 `不动 / 继续观察`。
泡泡玛特专属追加纪律： 从验证仓往上加之前，必须额外确认 `新IP接力`、`老IP不掉队`、`多IP协同成立`、`海外增长质量持续`。 这里的外部数据至少要覆盖：官方披露、渠道/平台客观数据、第三方或搜索热度旁证三类，避免只靠财报滞后验证。 若只是出现单次销售更新很强，但没有利润率、IP拆分和库存/渠道质量的配套确认，默认只做持有加分，不直接追高升级仓位。 若出现 `新IP未接力`、`老IP明显掉队` 或 `海外热度快速回落`，即使财报数字好看，也不允许直接升级仓位。

固定理解： `7+1` 回答的是“长期由谁构成组合”，不是“任何时点都必须 95% 股票仓位”。 当目标席位没到价时，回流出来的现金应视为 过渡期等待资本，而不是系统出错。
与资金结构联动： 股票仓位状态带只回答“当前该打到多高的股票暴露”；真正决定你年化上限的，还取决于这部分股票里，底仓 / 进攻仓 / V6-A / 现金各自占了多少。
边界补充： 状态带看的是有效股票仓位质量，不是只看股票比例本身。 若 `90%+` 的股票暴露主要是由 `腾讯 / PDD` 历史超配、旧仓残留或未迁移完成的结构撑出来，不算进攻态。 真正的进攻态必须同时包含合理比例的 ADBE / V6 或其他经过验证的新引擎；Radar 只算研究输入，不算进攻仓本身。
禁止误用： 不允许为了把股票仓位硬打到 95%，在 `ADBE / NU / 泡泡玛特 / 紫金` 等尚未进入舒服区时强行高价上仓。

交易增强层与 V6 策略纪律

2026-05-17 AI 右尾期权袖珍仓前置完成： 该模块已经制度化为 Radar / V6-B 的定义风险右尾表达，不是主仓替代品，也不是暴富模块。 候选池包括 AI 光互连、数据中心电力、HPC、存储、先进封装等方向；当前只允许研究和只读筛选，等待 2026-05-26 pilot 总结 与 2026-06-01 K 线额度刷新 后，再按执行卡决定是否出现第一批样本。

系统定位

  • Wheels / 期权脚本 与 自动化交易脚本 都属于整体账户收益增强层。
  • 它们服务主策略，不单独构成主策略，不允许反客为主。
  • V3 更像现金增强 / 停泊工具；V6 是独立进攻策略仓，必须单独记账。
  • 工具回答的是：当下最优动作，而不是长期仓位身份。

统一使用规则

  • 先看席位角色与主计划，再决定是否调用脚本。
  • 先算最坏情况仓位，再看价格，再看权利金或策略收益。
  • 只在准备动手时跑脚本：价格到关键区间、验证状态变化、准备调仓或准备卖 put。
  • V6-A 扩容必须按 5k pilot → 5%-8% → 10%-12% 三段走，并通过 deterministic replay、实盘可交易性、周报/月报与回撤阈值。V6-B 先证明 Sharpe、回撤和可执行性，再并入整体 V6。
固定口径： 价值主仓先行，增强层与策略仓后置；先判断这笔钱属于长期席位、V6 策略预算，还是现金等待资本，再决定执行工具。

反复杂化决策纪律

三层拆分

  • 研究层：财报、非财报验证、行业资料、机会成本比较、外部搜索。
  • 决策层：只回答 `买 / 加 / 减 / 不动` 与席位去留。
  • 执行层：挂单、wheels、V3、现金停泊等具体工具动作。

主变量上限

  • 永久席位：最多 `4` 个主变量：商业/人、价格、仓位、机会成本。
  • 验证仓：在永久席位基础上，只额外加 `验证状态` 这一项。
  • 灵活席位 / wheels：最多 `3` 个主变量：价格、最坏情况仓位、是否优于不动。

默认动作

  • 默认输出永远是 `不动`。
  • 只有当主变量清晰、价格到位、仓位允许、机会成本通过时，才允许升级成动作。
  • 若需要 `5-6` 个以上条件同时成立，默认降级为观察或小仓。
每次动作前强制一句： `这笔钱如果赚到，最主要靠哪 1-2 个变量成立？`
系统瘦身要求： 每季度至少做一次“删规则”复盘。凡是明显增加判断环节、但不明显提高胜率的规则或模块，优先合并或降级，避免研究复杂度溢出到决策层。
